# IM-BCI8 Hardware

This document describes the electronic architecture of the first IM-BCI8 hardware revision (**Rev.A**).

The goal of Rev.A was not to design a certified biomedical instrument. It was to build a compact, low-cost and reproducible 8-channel EEG acquisition board around the ADS1299, integrate wireless communication and battery operation, and leave enough flexibility for continued firmware and hardware experimentation.

> **Status:** Rev.A prototype assembled and operational  
> **Use case:** Experimental EEG / BCI development  
> **Not a medical device**

For safety requirements, limitations and human-use rules, see [`../SAFETY.md`](../SAFETY.md).

---

## 1. Design goals

The main design targets for Rev.A were:

- 8 simultaneous EEG channels;
- ADS1299-based biopotential acquisition;
- wireless operation without an external acquisition dongle;
- direct browser access through an ESP32-S3;
- single-cell LiPo operation;
- integrated battery charging;
- compact PCB size;
- low component count and low one-off prototype cost;
- fully editable KiCad sources;
- simple reproduction with commonly available PCB manufacturing services.

The design intentionally prioritizes **cost, integration and simplicity** over protection against every possible misuse.

That trade-off is documented throughout this repository rather than hidden.

## 2. High-level architecture

```text
             CH1 ... CH8
                  │
            4.7 kΩ / 4.7 nF
                  │
                  ▼
             ┌─────────┐
REF / SRB1 ─►│         │
BIAS ◄───────│ ADS1299 │
             │         │
             └────┬────┘
                  │ SPI
                  ▼
             ┌───────────┐
             │ ESP32-S3  │
             │  N8R8     │
             └─────┬─────┘
                   │
        ┌──────────┼──────────┐
        │          │          │
      Wi-Fi      Web UI      OTA
```

Power is generated from a single-cell LiPo battery using three separate rails:

```text
LiPo / VBAT
   │
   ├── AP2112K-3.3 ─────────────► +3V3_DIG ─► ESP32-S3
   │
   ├── LP5907MFX-3.3 ───────────► +3V3_AFE ─► ADS1299 DVDD
   │
   └── TPS61099 adjustable
          │
          ▼
       +5V_BOOST
          │
       ferrite
          │
          ▼
       +5V_AFE ─────────────────► ADS1299 AVDD / AVDD1
```

The analog and digital 3.3 V rails are therefore generated by separate regulators.

## 3. Main components

| Function | Component | Notes |
| --- | --- | --- |
| EEG analog front-end | **Texas Instruments ADS1299** | 8-channel, 24-bit biopotential AFE |
| Main MCU / radio | **ESP32-S3-WROOM-1-N8R8** | Wi-Fi, web server, acquisition control and OTA |
| Digital 3.3 V regulator | **AP2112K-3.3** | Supplies the ESP32-S3 domain |
| AFE 3.3 V regulator | **LP5907MFX-3.3** | Low-noise rail for ADS1299 DVDD |
| Analog boost | **TPS61099DRV** | Adjustable boost used to generate the analog supply |
| Analog rail filtering | **BLM18KG601BH1D** | Ferrite between `+5V_BOOST` and `+5V_AFE` |
| LiPo charger | **MCP73831-2-OT** | Single-cell linear LiPo charger |
| USB ESD protection | **USBLC6-2SC6** | Protects USB D+ / D- |
| Battery connector | 2-pin connector | `VBAT` + GND |
| EEG connector | 10-pin connector | BIAS, REF and eight channels |

The selected ESP32 module is the **N8R8** variant used on the current PCB.

## 4. ADS1299 analog front-end

The ADS1299 is the core of the acquisition board.

Rev.A uses:

- all 8 positive channel inputs;
- the internal SRB1 switching architecture for a common reference;
- the ADS1299 BIAS amplifier;
- internal reference operation;
- external analog and digital supply rails;
- SPI communication with the ESP32-S3.

The current firmware operates the board at **250 samples per second** during normal EEG acquisition.

The hardware itself is not conceptually limited to 250 SPS; this is the current firmware operating point and was selected as a practical EEG default.

### ADS1299 supply configuration

The final Rev.A schematic uses:

```text
AVDD / AVDD1  → +5V_AFE
DVDD           → +3V3_AFE
AVSS / DGND    → GND
CLKSEL         → +3V3_AFE
PWDN           → +3V3_AFE
CLK            → GND
DAISY_IN       → GND
RESV1          → GND
```

`PWDN` is therefore held high in Rev.A and is **not controlled by the ESP32**.

`RESET`, `START` and `CS` are externally controlled, with passive default-state resistors on the ADS1299 control lines.

### Internal support capacitors

The ADS1299 internal reference and charge-pump nodes use the following values in Rev.A:

| Node | Rev.A value |
| --- | ---: |
| VCAP1 | 100 µF polymer |
| VCAP2 | 1 µF |
| VCAP3 | 1 µF + 100 nF |
| VCAP4 | 1 µF |
| VREFP–VREFN | 10 µF + 100 nF |

These capacitors were placed close to the corresponding ADS1299 pins because these nodes are particularly sensitive to layout and supply noise.

## 5. EEG inputs

Each of the eight external signal channels follows the same basic topology:

```text
Electrode
   │
 4.7 kΩ
   │
   ├────────► ADS1299 INxP
   │
 4.7 nF
   │
  GND
```

The 4.7 kΩ / 4.7 nF network is mainly used for input current limiting and high-frequency filtering.

It should **not** be interpreted as complete medical-grade input protection.

The negative channel inputs are not routed to individual external electrodes. During normal referential acquisition, the firmware uses the ADS1299 internal SRB1 switching to connect the channel negative inputs to the common reference.

### External connector J2

| J2 pin | Function |
| ---: | --- |
| 1 | BIAS |
| 2 | REF / SRB1 |
| 3 | CH1 |
| 4 | CH2 |
| 5 | CH3 |
| 6 | CH4 |
| 7 | CH5 |
| 8 | CH6 |
| 9 | CH7 |
| 10 | CH8 |

The current development headset maps the eight signal channels to:

```text
CH1 → Fp1
CH2 → Fp2
CH3 → C3
CH4 → C4
CH5 → P7
CH6 → P8
CH7 → O1
CH8 → O2
```

This mapping is a current experimental configuration, not a hardware restriction.

## 6. Reference / SRB1 path

The common reference electrode enters through J2 pin 2.

Rev.A uses:

```text
REF electrode
     │
   4.7 kΩ
     │
     ├────────► SRB1
     │
   4.7 nF
     │
    GND
```

This gives the reference path a filtering topology similar to the eight signal inputs.

The SRB1 connection is then enabled or disabled by firmware depending on the selected ADS1299 acquisition mode.

---

## 7. BIAS circuit

The ADS1299 BIAS output is exposed on J2 pin 1 through a 4.7 kΩ series resistor.

The Rev.A BIAS compensation network is:

```text
BIASOUT ──┬── 1 MΩ ──┐
          │           │
          └── 1.5 nF ─┤
                      │
                   BIASINV
```

and:

```text
BIASOUT ── 4.7 kΩ ──► J2 pin 1 / BIAS electrode
```

BIAS can be enabled or disabled by firmware.

The current firmware intentionally allows the board to be tested first with BIAS disabled, then compared with BIAS enabled once the basic electrode/reference path is confirmed.

## 8. ESP32-S3 and digital interface

Rev.A uses an **ESP32-S3-WROOM-1-N8R8** module.

The ESP32 handles:

- ADS1299 configuration;
- SPI acquisition;
- DRDY synchronization;
- buffering;
- Wi-Fi access point operation;
- browser interface hosting;
- CSV acquisition support;
- OTA firmware updates;
- status LED control.

### ADS1299 ↔ ESP32-S3 mapping

| ADS1299 signal | ESP32-S3 GPIO |
| --- | ---: |
| START | GPIO8 |
| RESET | GPIO9 |
| CS | GPIO10 |
| MOSI / DIN | GPIO11 |
| SCLK | GPIO12 |
| MISO / DOUT | GPIO13 |
| DRDY | GPIO14 |

The current firmware uses a deliberately modest SPI clock for robust bring-up and acquisition.

### Status LED

D1 is connected to **GPIO4** through a 1 kΩ resistor.

It is available as a firmware-controlled status indicator.

### Boot control

GPIO0 includes a 10 kΩ pull-up and a physical push button for manual boot/programming support.

## 9. Power architecture

Power integrity was one of the main design concerns because the board combines a Wi-Fi MCU, a switching converter and a low-noise biopotential AFE.

### `+3V3_DIG`

```text
VBAT
  │
AP2112K-3.3
  │
+3V3_DIG
  │
ESP32-S3
```

This rail supplies the digital / wireless domain.

### `+3V3_AFE`

```text
VBAT
  │
LP5907MFX-3.3
  │
+3V3_AFE
  │
ADS1299 DVDD
```

A separate low-noise regulator is used for the ADS1299 digital supply rather than sharing the ESP32 rail.

### `+5V_AFE`

The ADS1299 analog supply is generated by an adjustable TPS61099 boost converter.

The feedback divider is:

```text
390 kΩ / 100 kΩ
```

which targets approximately **4.9 V** before analog filtering.

The raw boost rail is named:

```text
+5V_BOOST
```

and then passes through a **BLM18KG601BH1D ferrite bead** to create:

```text
+5V_AFE
```

used by the ADS1299 analog supply pins.

The first assembled prototype measured the analog rail close to the intended value during bring-up.

## 10. Power switch strategy

Rev.A does not route the entire board current through the mechanical switch.

Instead, SW2 is used as a logic-level enable selector:

```text
SW2 ON
PWR_EN = VBAT
→ regulators enabled
→ board ON

SW2 OFF
PWR_EN = GND
→ regulators disabled
→ board OFF
```

`PWR_EN` also has a 100 kΩ pull-down.

This architecture allows the battery charger to remain connected to the cell while the rest of the system is switched off.

As a result:

```text
USB connected
+
SW2 OFF
=
battery can charge while the EEG electronics remain off
```

This was a deliberate design choice.

## 11. USB-C and battery charging

USB-C serves two development functions:

- ESP32-S3 USB programming / communication;
- LiPo charging.

### Native ESP32-S3 USB

The native ESP32-S3 USB signals use:

```text
USB D- → USBLC6 → 22 Ω → GPIO19
USB D+ → USBLC6 → 22 Ω → GPIO20
```

The USB-C CC pins use 5.1 kΩ pull-down resistors.

### LiPo charging

VBUS feeds an **MCP73831-2-OT** charger.

Rev.A uses:

```text
RPROG = 2 kΩ
```

corresponding to a nominal charge-current configuration of approximately 500 mA for the selected charger configuration.

The battery used with the system must therefore be suitable for the configured charging current.

The charger uses 4.7 µF local capacitors on its VDD and VBAT sides.

### Charge indicator

D2 is connected to the MCP73831 `STAT` output through a 1 kΩ resistor from `VBUS_USB`.

Expected behavior:

```text
USB absent                  → D2 OFF
USB present, charging       → D2 ON
charge terminated / full    → D2 OFF
```

The MCP73831 is a charger, not a complete power-path controller.

For normal use, charging the battery with the main electronics switched off is preferred.

## 12. Important safety architecture

There is **no galvanic isolation between USB ground and the EEG electronics** in Rev.A.

This means that the USB port must be treated as a development / charging interface, not as a simultaneously connected interface during human EEG acquisition.

When electrodes are connected to a person:

```text
USB disconnected
charger disconnected
laboratory PSU disconnected
grounded oscilloscope disconnected
function generator disconnected
battery power only
wireless communication only
```

This limitation is fundamental to Rev.A and is not solved by firmware.

See [`../SAFETY.md`](../SAFETY.md) before reproducing or using the hardware.

## 13. Rev.A design trade-offs and known limitations

Rev.A was intentionally kept compact and relatively minimal.

### What Rev.A prioritizes

- low one-off cost;
- small component count;
- compact integration;
- integrated Wi-Fi;
- integrated charging;
- easy firmware iteration;
- straightforward PCB reproduction;
- accessibility for experimental BCI work.

### What Rev.A does not provide

- reverse-polarity protection on the battery connector;
- medical-grade galvanic isolation;
- medical-grade input protection;
- dedicated battery-voltage measurement;
- a true charger / system power-path controller;
- protection against every possible wiring or handling error;
- certification as biomedical or consumer equipment.

The absence of reverse-polarity protection is particularly important: **battery polarity must be checked before connection**.

The 4.7 kΩ input resistors and RC networks must not be interpreted as sufficient patient-protection circuitry for a certified medical device.

The current board should be treated as **experimental laboratory / maker hardware**.

## 14. Rev.A bring-up status

The first assembled Rev.A board has successfully passed the main bring-up stages:

- digital 3.3 V rail operation;
- AFE 3.3 V rail operation;
- boosted analog rail operation;
- ESP32-S3 boot and Wi-Fi operation;
- ADS1299 SPI identification;
- ADS1299 internal test signal;
- ADS1299 internal short/noise testing;
- all eight physical signal paths;
- external signal acquisition across all eight channels;
- battery operation;
- USB charging;
- browser-based acquisition;
- OTA firmware update.

Detailed measurement protocols and raw characterization data are kept separate from this hardware document and belong in [`../characterization/`](../characterization/).

This separation is intentional: the hardware documentation describes **what the board is**, while the characterization section describes **how well it performs**.

## 15. Manufacturing cost

The Rev.A PCB and electronic components cost approximately:

**~$150 USD in one-off prototype quantities**

This number is intended as an order-of-magnitude reproducibility figure rather than a guaranteed BOM price.

It excludes:

- soldering / assembly labor;
- tools;
- shipping;
- import duties and taxes;
- failed parts or spare components;
- development time.

A structured BOM will be provided in the manufacturing directory so the cost can be recalculated as component prices change.

## 17. Rev.B candidates

Rev.A is intentionally being characterized before a second board revision is frozen.

Potential Rev.B improvements currently include:

- battery reverse-polarity protection;
- battery-voltage sensing by the ESP32;
- improved input protection;
- additional ESD protection where appropriate;
- review of charger / system power-path behavior;
- additional hardware test points;
- improvements suggested by Rev.A characterization and community feedback.

These are candidates, not promises: changes should be driven by measured limitations rather than added only for feature count.

## 18. Reproduction philosophy

The goal of publishing the hardware is not only to provide Gerbers.

A reproducible open-hardware project should make it possible to understand:

1. what each circuit block does;
2. which compromises were made;
3. how the board should be assembled;
4. how the first power-up should be performed;
5. which measurements indicate correct operation;
6. which known failure modes exist;
7. how a modified design differs from the tested reference.

For that reason, assembly, bring-up and troubleshooting are documented separately instead of being compressed into this file.
